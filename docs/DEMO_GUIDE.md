# 三分钟演示稿

## 0:00—0:30｜问题与定位
回声面向需要同时处理App、活动和内容反馈的小团队。它帮助用户把原话、推断和行动分开，保留人工判断。当前为个人作品集原型，公开样本均为构造数据。

## 0:30—1:20｜展示E01
进入“证据与问题”，打开E01。展开原文：用户觉得切换麻烦，后来退出。这里不能直接得出“切换导致退出”。填写“是什么、为什么这样判断、下一步怎么做”，先核实操作和退出原因，再决定是否改功能。

## 1:20—2:00｜验证AI与设计取舍
展开更多，展示历史分析。v2和v3相同8条案例均通过13/16项判据，但v3耗时及Token增加。没有宣称升级必然更好，而是改用事实、缺口、假设分离的结构。语义判断仍需人工审核。

## 2:00—2:40｜形成行动并证明保存
保存判断，加入待办，说明可以先安排补充证据而非开发功能。刷新页面，确认记录保留；导出JSON作为备份。数据仅在本机浏览器中，不跨设备同步。

## 2:40—3:00｜贡献与局限
本人负责场景范围、字段设计、流程取舍与审核标准，使用Codex辅助编码和初步评测。未完成外部用户对照研究，不声称商业转化或人工效率提升。下一步将验证真实用户的审核耗时及修订质量。

# 面试准备
- 为什么不做自动采纳？原文匹配不能保证语义正确，人工确认成本低于错误需求的后续成本。
- 为什么只保留三个字段？此前信息重复且按钮过多；将证据与历史折叠，使主要任务聚焦于判断与行动。这是本次交互改动，尚无用户测试证明更高效。
- 为什么公开版不接实时模型？无需密钥即可体验审核流程；真实API能力在本地模式验证，避免访客误用个人额度。
